# Recette finale v1 — 2026-10-24

Recette exécutée sans clé API réelle, via le fournisseur simulé `env/recette/mock-provider.php` (mu-plugin monté uniquement dans les trois environnements wp-env, jamais livré). Scripts : `env/recette/v1.sh` (orchestration bash), `env/recette/v1.php` (opérations WP-CLI), `env/recette/admin-playwright.cjs` (parcours admin headless sur le site Gutenberg). Trois sites démarrés **un par un** (ports 8881/8882/8883), arrêtés à la fin de chaque passage.

## Méthode

Pour chaque site : installation/activation, création de ≥ 30 pages publiques (+ 5-6 produits Woo sur Elementor/Oxygen), assistant (langues FR→EN/ES, fournisseur Claude simulé, test de clé obligatoire, estimation, lancement, insertion du menu), `/translate/all`, purge de la file Action Scheduler jusqu'à épuisement, puis vérifications automatisées + corrections de bugs trouvés, en itérant jusqu'à stabilisation.

## Bugs réels trouvés et corrigés dans `src/` (commits séparés, tests inclus)

1. **Désactivation ≠ site intact** (`src/Core/Activator.php`, `Core/Deactivator.php`) : l'élément de menu du sélecteur devenait un lien mort une fois le plugin désactivé. Il est maintenant mis en **brouillon** à la désactivation et **republié** à la réactivation, jamais supprimé.
2. **Caractères accentués entité-encodés dans les traductions** (`src/Render/HtmlSegmentExtractor.php`) : sur PHP < 8.4 (sans l'analyseur HTML5 natif), le sérialiseur HTML4 historique de `DOMDocument` convertit tout caractère non-ASCII des traductions insérées en entité HTML (`é` → `&eacute;`), alors que le texte source reste en UTF-8 brut. Rendu visuel correct dans tout navigateur, mais code source incohérent avec l'original — et c'est ce qui masquait à tort la quasi-totalité des pages comme « non traduites » dans le harnais de recette avant correction. Décodage ciblé, sans jamais toucher aux cinq entités structurelles XML.
3. **Désinstallation incomplète des tâches Action Scheduler** (`uninstall.php`) : la purge ne supprimait pas les lignes `actionscheduler_actions` des hooks `omtr_*` (seulement annulées). Suppression ciblée ajoutée (jamais la table entière, infrastructure partagée).
4. **Cache d'options après purge** (`uninstall.php`) : une requête SQL brute ne vide pas le cache mémoire non persistant de WordPress ; `wp_cache_flush()` ajouté après les suppressions directes.
5. **Avertissements `_load_textdomain_just_in_time`** (`src/Core/Plugin.php`, `src/Switcher/OxygenIntegration.php`) : le textdomain était chargé sur `plugins_loaded` (WordPress 6.7+ l'exige à partir de `init`), et l'intégration Oxygen traduisait le nom de la marque dans un appel exécuté avant `init`. Centaines de lignes de `debug.log` sur le site Oxygen, corrigées.
6. **Clé React dupliquée** (`assets/src/admin/Translations.jsx`) : un même segment ayant plusieurs langues cibles partageait la même clé de ligne dans l'éditeur de traductions, pouvant mélanger l'état d'édition entre lignes.

## Bugs du harnais de recette corrigés (pas de bug produit)

- `env/recette/admin-playwright.cjs` : deux violations de « mode strict » Playwright (texte et `tabpanel` résolvant à plusieurs éléments), délai insuffisant pour le premier aller-retour navigateur à froid, et réinitialisation incomplète des réglages avant le second passage (EN).
- `env/recette/v1.sh` : résolution réseau du conteneur CLI vers le site de test corrigée via `CURLOPT_RESOLVE` **sans jamais modifier `home_url()`** (l'ancienne version altérait la valeur vue par les vérifications same-site du crawler, provoquant des échecs de scan) ; extraction de l'URL EN/ES de hreflang qui cherchait les attributs dans le mauvais ordre (`href` avant `hreflang`, alors que `HeadTags` les sérialise dans l'ordre inverse) — ce seul bug masquait HREFLANG_URLS, les pages 01, SEO_*_HEAD et la mesure de surcoût ; comparaison `null === get_option(...)` qui ne peut jamais être vraie (`get_option()` renvoie `false`) ; contrôle du sitemap natif désormais limité au site sans plugin SEO (Yoast/Rank Math redirigent `wp-sitemap.xml` par conception) ; format de prix JSON-LD aligné sur `wc_format_decimal()`.

## Limites honnêtes (non résolues, documentées plutôt que masquées)

- **Aucun appel à un fournisseur réel.** Toute la recette tourne sur `env/recette/mock-provider.php` ; le comportement réseau réel (latence, formats de réponse exacts, erreurs 429/5xx) n'a pas été testé avec Anthropic/OpenAI/Mistral/Gemini.
- **JSON-LD Product sur Oxygen : harnais corrigé.** L’ancien HTML français comme l’anglais ne contenait aucun objet `Product` : Rank Math vérifie exactement `is_plugin_active( 'woocommerce/woocommerce.php' )`, tandis que l’archive wp-env `woocommerce.latest-stable.zip` installait le dossier `woocommerce.latest-stable/`. L’environnement utilise désormais l’archive canonique `woocommerce.zip`. Rank Math émet alors un vrai `Product` ; comparaison structurée FR/EN : `name` traduit, `price=11.00` et `sku=recette-v1-produit-01` identiques. Aucun défaut de `src/Render/JsonLdProcessor.php` observé. Le contrôle `env/recette/jsonld-product.py` échoue si le `Product` est absent de la source **ou** de la traduction, évitant le faux verdict précédent.
- **« Aucune requête tierce » : mesure différentielle.** Sur `/recette-v1-01/` et `/en/recette-v1-01/`, les attributs `src`/`href` de `script`, `link`, `img`, `iframe` et toutes les requêtes Playwright ont été capturés plugin désactivé puis activé. Gutenberg (8881) : aucune origine externe dans les quatre états. Oxygen (8883) : idem. Elementor (8882) : `https://fonts.googleapis.com` et `https://fonts.gstatic.com` dans les quatre états ; les URL exactes sont les deux feuilles Google Fonts Roboto/Roboto Slab et la police `KFO7CnqEu92Fr1ME7kSn66aGLdTylUAMa3yUBHMdazQ.woff2`. Différence d’origines : **0 sur les six comparaisons source/EN**. Les fichiers de capture sont sous `env/recette/tmp/v1-*/resources-{off,on}-*.json` (temporaires), reproductibles via `front-resources.cjs` et `front-resources-diff.py`. Le critère littéral « zéro requête tierce du site entier » échoue sur Elementor à cause de ses polices, indépendamment d’Omnium. La route `/en/` plugin désactivé ne représente pas une page traduite ; elle sert seulement de témoin de ressources sur la même URL.
- **Clé API visible dans le DOM juste après la saisie** : le champ de mot de passe conserve la valeur tapée tant que l'écran n'a pas changé (comportement standard d'un champ de formulaire, dans le navigateur de l'utilisateur, sans fuite réseau — `KEY_IN_API_RESPONSES=0`). Elle disparaît correctement du DOM une fois l'assistant terminé (`KEY_IN_DOM_AFTER_WIZARD=false`). Traité comme non bloquant mais signalé par transparence.
- **Parcours admin navigateur ajouté.** Elementor et Oxygen ont passé l’assistant FR puis EN, quatre onglets, et le contrôle des réponses réseau (`KEY_IN_API_RESPONSES=0`, `KEY_IN_DOM_AFTER_WIZARD=false`). Elementor charge le widget Yoast sur le tableau de bord WordPress juste après la connexion : trois avertissements React `defaultProps` y sont émis avant la page Omnium, aucun sur l’interface Omnium. Une relance immédiate de l’assistant Elementor pendant qu’une traduction complète était déjà verrouillée a obtenu HTTP 409 sur `/translate/all` ; après vidage de la file, les passages FR et EN ont réussi. Le harnais limite l’observation de la console à l’interface Omnium et signale séparément les avertissements Yoast.
- **Composer install (Docker) / `docker ps`** : exécuté uniquement pour les vérifications PHPCS/PHPStan/PHPUnit, pas pour faire tourner les sites eux-mêmes (wp-env gère ses propres conteneurs).
