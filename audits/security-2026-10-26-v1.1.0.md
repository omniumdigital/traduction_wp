## Étape 3 — Revue manuelle
### 3.2 Contrôle d'accès — OK
La route `POST /omtr/v1/translations/retry` est déclarée dans la table `$routes` de
`Administration::register_routes()` (src/Admin/Administration.php:180) et reçoit donc le même
`permission_callback = Capabilities::rest_permission` (`omtr_manage`) que toutes les autres
routes : vérifié par `AdministrationSecurityTest::test_all_routes_require_manage_capability`
(10 routes, mises à jour dans le test).

### 3.3 Clés API — OK
`retry_failed()` répond par un `WP_Error` 409 dont le message vient de `last_reason()` :
texte traduit, sans clé ni réponse brute du fournisseur. La réponse de succès ne contient que
`{retried: int}`. Aucun masque ni matériau de clé manipulé.

### 3.4 Abus et coûts — OK (amélioré)
Le point d'entrée appelle `provider_is_ready()` **avant** toute mise en file
(src/Admin/Administration.php:470-473) : sans clé configurée, rien n'est mis en file et la
raison est renvoyée (testé : `test_retry_refused_without_key`, 409). La relance passe ensuite
par `enqueue_segments()` (src/Admin/Administration.php:481) qui applique de nouveau la garde,
les quotas horaires et le plafond mensuel, et saute tout segment déjà traduit (« jamais payé
deux fois ») ; la langue cible de chaque segment en échec est respectée.

### 3.1 / 3.5 / 3.6 / 3.7 — OK
Aucun changement du DOM de rendu, du réseau, des imports/exports ou du schéma ; l'option
`omtr_words_translated` reste déclarée dans `Options::all()` (purge à la désinstallation).
`provider_is_ready()` est un ajout à la classe concrète `ActionSchedulerQueue`, pas au contrat
figé `TranslationQueueInterface`.
