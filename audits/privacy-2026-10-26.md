## Checklist

### Étape 2 — Ce qui part vers l'IA — OK
- Crawler sans cookie : `'cookies' => array()` (`src/Queue/ScanJob.php:216`), plus `'Cookie' => ''` (`src/Queue/PublicContent.php:106-107`), `redirection => 0`.
- Exclusions : admin, cron, AJAX hors fragments Woo, REST, éditeurs de builders (`src/Router/RequestGuard.php:20-37`) ; utilisateur connecté, prévisualisation, mot de passe, panier, commande, compte, `order-received` (`src/Router/RequestGuard.php:47-58`) ; uniquement des contenus `publish` de types publics, non protégés, hors pages panier/commande/compte Woo (`src/Queue/PublicContent.php:36,160-178`).
- À la volée jamais pour un utilisateur connecté : `is_crawlable_or_ai_eligible()` appelé avant toute mise en file (`src/Queue/OnTheFlyTrigger.php:74`) ; option désactivée par défaut.
- Filtre PII : emails, téléphones, IBAN avec checksum, cartes avec Luhn (`src/Security/PiiFilter.php:24-107`), appliqué à chaque segment (`src/Render/HtmlSegmentExtractor.php:340`). Un test par motif (`tests/Unit/PiiFilterTest.php:25-45`).
- Champs de formulaire : attributs extraits limités à `alt, title, placeholder, aria-label` (`src/Render/HtmlSegmentExtractor.php:20`), contenu des `textarea` exclu (`:288-290`) ; test `tests/Unit/HtmlSegmentExtractorTest.php:20-21` (`value="Secret"` et contenu de textarea non extraits).
- Emails Woo : seuls les gabarits de réglage (sujet, titre, contenu additionnel), jamais la valeur formatée avec les données de commande (`src/Woo/EmailTemplateTranslator.php:75-140`).
- Prompt : règles, langues, ton, contexte et glossaire uniquement ; segments déclarés comme données non fiables (`src/Providers/PromptBuilder.php:45-87`). Aucune URL d'admin ni nom d'utilisateur.

### Étape 3 — Stockage et journaux — OK
- Messages de log techniques (identifiants, compteurs, code HTTP, langue), nettoyés et tronqués à 500 caractères (`src/Store/DbLogger.php:37-41`) ; revue de chaque appel dans `src/Queue/*.php` : aucun texte de segment, clé, IP ni identifiant utilisateur.
- Purge 30 jours : tâche Action Scheduler quotidienne (`src/Store/DbLogger.php:57-74`, branchée `src/Store/StoreModule.php:42-43`).
- Erreurs fournisseur : seul le code HTTP est journalisé (`src/Queue/BatchJob.php:170-183`), messages d'exception génériques.
- Aucune donnée visiteur : aucune lecture de `REMOTE_ADDR`, `HTTP_USER_AGENT` ou `get_current_user_id()` dans `src/`.
- Exports : configuration JSON sans clé (`src/Admin/Administration.php:454-471`) ; CSV du glossaire limité aux colonnes du glossaire.

### Étape 4 — Côté visiteurs — OK
- Aucun cookie par défaut : `pref_cookie => false` (`src/Core/Settings.php:32`) ; l'attribut `data-omtr-pref` n'est émis que si l'option est active (`src/Switcher/Switcher.php:177`), seul déclencheur du cookie (`assets/src/switcher/index.js:17-24`). Cookie `omtr_lang` = code langue validé, `Max-Age=31536000` (12 mois), `SameSite=Lax`, `Secure` en HTTPS.
- Aucun `localStorage` / `sessionStorage`.
- Aucune ressource tierce dans les sources front (contrôle statique ci-dessus). La mesure réseau Playwright de la recette v1 (`audits/recette-v1-2026-10-24.md`) reste valable : les modifications de `assets/css/switcher.css` de cette release n'ajoutent aucune URL.
